# 馥屿网站使用与维护说明

更新日期：2026-07-13

## 1. 项目是什么

馥屿（ScentAtoll）是一个香水电商网站，正式域名为 `https://scentatoll.com`。

- 顾客端：浏览商品、注册登录、管理地址、下单、查看订单、确认收货、申请退款、查看积分和兑换积分商品。
- Owner 管理端：核对人工转账、发货、填写物流、退款、管理商品和库存、管理会员及积分商城。
- 第一阶段收款：微信人工转账，由 Owner 在后台核款。
- 微信支付 API v3 尚未开启；没有商户号、AppID 和证书前必须保持 `WECHAT_PAY_ENABLED=false`。

## 2. 前端使用什么

前端不是 React/Vue 项目，而是使用 Eleventy 生成的多页面网站：

- 页面模板：`网页制作/src/pages/*.njk`
- 公共布局与组件：`网页制作/src/_includes/`
- 浏览器模块：`网页制作/src/assets/js/*.js`
- 生成的浏览器 bundle：`网页制作/src/assets/script.js`，不要跳过源模块直接维护它
- 样式：`网页制作/src/assets/styles.css`
- 商品初始数据与本地开发数据：`网页制作/src/assets/data.js`
- 构建输出：`网页制作/dist/`，不要直接手工修改这里的生成文件。

常见修改：

- 改页面文字或结构：编辑对应 `.njk` 文件。
- 改颜色、间距、响应式布局：编辑 `src/assets/styles.css`。
- 改前端交互：编辑 `src/assets/js/*.js`，然后运行构建更新 bundle。
- 改后台界面：重点查看 `src/pages/admin.njk` 和对应后台脚本。
- 改完后运行 `npm run build`，浏览生成结果。

## 3. 后端使用什么

后端是 Node.js 22 的原生 HTTP 应用，部署为 Vercel Functions：

- 应用入口：`网页制作/server/src/app.mjs`
- Vercel API 入口：`网页制作/api/[...path].mjs`
- 商品服务端页面：`网页制作/api/product-page.mjs`
- 服务模块：`网页制作/server/src/services/`
- 数据库迁移：`网页制作/server/migrations/`
- 自动化脚本：`网页制作/scripts/`
- 自动测试：`网页制作/tests/`

本地没有 `DATABASE_URL` 时可使用 JSON 开发数据；Vercel Production/Preview 必须使用 PostgreSQL，禁止回退 JSON。

## 4. 用到的网站和作用

| 平台 | 项目中的作用 | 修改入口 |
| --- | --- | --- |
| GitHub | 保存代码、PR、自动测试和定时释放超时库存 | `github.com/zdon7237-ctrl/scent-` |
| Vercel | 正式站、Preview、Node API、域名和环境变量 | Vercel 项目 `scent-atoll/scent` |
| Neon | PostgreSQL，保存账号、商品、订单、库存、积分和审计数据 | Vercel Storage 中的 `scent-postgres` |
| Vercel Blob | 保存后台上传的公开商品图片 | Vercel Storage 中的 `scent-blob` |
| Upstash Redis | 登录限流，阻止暴力尝试密码 | Vercel Storage 中的 `scent-redis` |
| Resend | 邮箱验证、找回密码、订单和发货邮件 | Vercel Marketplace 中的 `scent-email` |
| Netlify | 只读应急降级与 PR 静态预览，不承载正式交易后端 | Netlify 项目 `scent-atoll` |

重要边界：

- GitHub 分支和 PR 不等于正式上线。
- Vercel Preview 只用于测试。
- 合并到 `main` 不会直接更新正式站：仓库门禁会跳过 Vercel Git 自动 Production；只有受保护工作流验证后 Promote 才会影响正式站。
- Neon、Blob、Upstash 和 Resend 都属于外部托管服务；不要在代码或聊天中粘贴真实密钥。

## 6. 商品和图片怎么修改

上线后数据库是商品唯一来源，不应只改 `data.js` 期待线上商品自动变化。

推荐流程：

1. Owner 登录管理端。
2. 进入“商品”。
3. 新建或编辑商品、规格、价格、库存和稳定 slug。
4. 在商品详情里上传、排序、替换或删除图片。
5. 保存后检查商品页、搜索结果、购物车与 `/sitemap.xml`。

商品 slug 会进入 `/products/:slug`，上线后不要随意修改；必须改时要保留跳转或检查旧链接。

## 7. 订单日常处理

Owner 后台优先处理四类任务：

1. 待核款：核对微信转账金额和参考号，再确认收款。
2. 待发货：填写承运商和物流单号后发货。
3. 待处理兑换：处理积分商城兑换及取消。
4. 低库存：补库存或下架商品。

积分在顾客确认收货后发放。核款、退款、发货、库存和积分操作都需要保留审计记录，不要直接改数据库绕过后台流程。

## 8. 邮件怎么修改

- 邮件服务代码：`网页制作/server/src/services/email-service.mjs`
- 发件人环境变量：`EMAIL_FROM`
- 建议正式发件人：`馥屿 <noreply@scentatoll.com>`
- 客服回复地址可使用 `EMAIL_REPLY_TO`。

更改发件地址前，应先在 Resend 验证 `scentatoll.com` 的 DNS。不要把未验证域名写进 Production。

## 9. 环境变量

变量示例见：

- `.env.production.example`
- `.env.preview.example`

Production 与 Preview 分开配置。核心变量包括：

- 网站：`SITE_URL`、`APP_ORIGIN`、`DEPLOYMENT_ENV`
- 联系资料：`CONTACT_EMAIL`、`CONTACT_WECHAT`、`BUSINESS_NAME`
- 数据库：`DATABASE_URL`
- 邮件：`RESEND_API_KEY`、`EMAIL_FROM`
- 图片：旧式 `BLOB_READ_WRITE_TOKEN`，或新版 `VERCEL_OIDC_TOKEN + BLOB_STORE_ID`
- 限流：旧式 `UPSTASH_REDIS_REST_*`，或 Marketplace 的 `UPSTASH_REDIS_KV_REST_API_*`
- 定时任务：`CRON_SECRET`

线上禁止：`SEED_ADMIN_EMAIL`、`SEED_ADMIN_PASSWORD`、`PAYMENT_WEBHOOK_SECRET`。

## 10. 发布流程

1. 从 `codex/` 或功能分支提交代码并推送 GitHub。
2. 创建 PR 到 `main`。
3. 等 GitHub CI 与 Vercel Preview 通过。
4. 在 Preview 验证注册、登录、商品、下单、核款、发货、确认收货、积分和退款。
5. 在隔离 Neon Preview 分支运行 migration 与 smoke test。
6. 确认环境变量、备份、告警和回滚版本。
7. 合并 `main`，确认 Vercel 自动 Production 显示 skipped，再运行受保护的 Production Release workflow。
8. 验证正式域名的页面、API、数据库和权限边界。

不要在 Vercel 构建阶段运行 migration 或 seed，也不要通过 `vercel env pull` 回拉 Sensitive env。生产发布顺序必须是外部设置审计、资源隔离、migration、Vercel 云端 candidate、验证、promote、正式域名复验。

## 11. 故障排查

- Vercel Schema 报错：检查根目录和 `网页制作/vercel.json`，再运行 `npm run check:deploy`。
- Preview 构建提示缺变量：查看 Vercel Environment Variables 的 Preview 作用域。
- 邮件不发：检查 Resend 域名状态、`RESEND_API_KEY`、`EMAIL_FROM` 和邮件投递日志。
- 图片上传失败：检查 Blob Store 连接、OIDC/Store ID 和图片类型/大小。
- 登录限流失败：检查 Upstash URL、Token 和免费额度。
- API 读不到商品：先检查 `/api/health/ready`、`/api/products` 和 Neon 连接。
- 正式站异常：不要立即修改数据库；先查看 Vercel Logs，必要时回滚到上一个 Deployment。
