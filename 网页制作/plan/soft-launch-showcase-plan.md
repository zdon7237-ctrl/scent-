# 馥屿展示 / 试运营版上线计划

> 历史方案：当前商业主生产已切换为 Vercel 完整 `dist/` + API。本文只描述 Netlify `dist-public/` 应急只读降级包，不得作为当前商业部署说明。

更新日期：2026-05-12

## 当前决策

先采用“展示 / 试运营版”上线，不在第一版开放真实在线支付。

这一版的目标不是把系统做成完整电商闭环，而是先让「馥屿 Scent Atoll」有一个可公开访问、品牌气质完整、移动端可用、基础 SEO 合格、合规信息齐全的网站。用户可以浏览香水、试香套装、品牌和买手内容，并通过客服或预约方式进入人工购买 / 试香咨询。

图片和商品内容当前允许继续使用外部图片与测试商品数据，作为设计和流程占位。真实商品图、授权图片和最终商品资料由店主在最后上线前统一替换，不作为本轮工程、部署、SEO 和合规收口的阻塞项。

## 当前执行状态

展示 / 试运营版的工程收口已经落到 public-only 发布包：

- `npm run build:public` 可输出本地 public-only 包；正式部署平台使用 `npm run launch:strict`，会先校验真实运营信息再生成 `dist-public/`。
- `npm run launch:check` 会构建发布包、检查公开包边界并校验 Netlify / Vercel 配置。
- 后台、会员、订单、积分和开发前端模块不会进入 `dist-public/`。
- SEO、robots、sitemap、favicon、品牌分享图、隐私政策、用户协议、人工购买说明、服务说明和 404 页面已补齐。

当前还不能视为“正式可上线”的原因不是工程缺口，也不是商品图片和商品资料，而是仍缺少真实运营信息：正式域名、客服邮箱和客服微信。经营主体名称可选，不设置时使用已确认店名 `馥屿 Scent Atoll`；工作室试香预约方式可选，不设置时使用 `通过客服微信预约`。填入后必须跑 `npm run launch:strict`，部署后再跑 `npm run check:live`。

## 上线版本边界

### 本阶段开放

- 首页。
- 香水列表。
- 商品详情。
- 品牌页。
- 试香套装页。
- Journal / 买手文章。
- 关于我们。
- 配送与退换 / 服务说明。
- 客服联系和工作室预约入口。
- 可选：购物车作为“意向清单”或暂时隐藏，不做真实支付。

### 本阶段不开放

- 真实在线支付。
- 自动创建真实订单。
- 会员积分正式运营。
- 积分商城正式兑换。
- 后台管理入口公开访问。
- 商品、品牌、文章后台化。
- 正式库存扣减、库存预留和支付回调。
- PostgreSQL 生产数据库切换。

### 必须避免的误导

- 页面不能让用户误以为已经可以直接在线付款。
- 结账按钮不能进入会失败的 `/api/checkout/*` 流程。
- 会员、积分、订单、后台等开发版能力不能作为公开主路径。
- 如保留购物车，应明确是“意向清单 / 咨询清单”，而不是已支付订单。

## 用户路径

### 主要路径

```text
进入首页 -> 查看香水 / 试香 -> 进入商品详情 -> 通过客服咨询或预约试香
```

### 辅助路径

```text
进入首页 -> 阅读品牌 / Journal -> 建立信任 -> 返回香水或试香套装
```

### 可选路径

```text
加入意向清单 -> 查看清单 -> 联系客服确认库存、价格和试香方式
```

如果不想在试运营阶段维护购物车，就把购物车入口隐藏，并把商品详情 CTA 改为“咨询这支香 / 预约试香 / 查看试香套装”。

## 阶段 0：收口当前工作区

### 目标

把现有已完成的设计、品牌名、导航、删除选香指南、计划文档清理等改动固定下来，避免后续上线收口时混进旧改动。

### 任务

1. 跑基础检查：

```bash
cd 网页制作
npm run build
npm test
node --check src/assets/js/app.js
node --check script.js
```

2. 确认 `dist/` 和根目录静态文件是最新构建产物。
3. 检查 `git status --short`，把已完成的前端和文档改动作为一个 checkpoint。
4. 如要提交，提交信息建议：

```text
Prepare Scent Atoll frontend and planning docs
```

### 验收

- 构建通过。
- 测试通过，允许 PostgreSQL smoke 在未设置 `DATABASE_URL` 时跳过。
- 工作区改动范围清楚。

## 阶段 1：试运营模式调整

### 目标

让网站公开访问时不会暴露“开发版交易系统”的不完整感。

### 任务

1. 决定购物车策略：
   - 方案 A：隐藏购物车，商品详情只保留咨询 / 试香 CTA。
   - 方案 B：保留购物车，但改名为“意向清单”，不调用真实结账 API。
2. 隐藏或弱化公开导航中的登录、注册、会员、积分、订单入口。
3. 确认 `admin.html` 不出现在任何公开导航、页脚或 sitemap 中。
4. 商品详情主 CTA 建议调整为：
   - `咨询这支香`
   - `预约试香`
   - `查看试香套装`
5. 如果保留“加入清单”，点击后只进入本地意向清单，不触发订单创建。
6. 空状态文案改为人工服务路径，例如“把想试的香加入清单后，通过客服确认库存和试香方式。”

### 验收

- 用户不会进入失败的支付 / 订单 API。
- 页面文案明确这是一版试运营咨询路径。
- 商品详情到联系客服或试香套装路径清楚。

## 阶段 2：移动端 header 和页面效率

### 目标

移动端首屏更快进入内容，减少顶部区域占用。

### 任务

1. 移动端公告栏从三列横排改为更轻的单行或可关闭提示。
2. 移动端 header 默认只显示品牌、菜单按钮、必要入口。
3. 搜索可以放进菜单展开区，避免常驻占满首屏。
4. 登录 / 注册在试运营阶段可移入菜单底部或暂时隐藏。
5. 商品详情移动端把咨询 / 试香 CTA 放在购买判断之后的明显位置。

### 验收

- 375px 宽度无横向溢出。
- 首页移动端首屏能看到品牌主文案和至少一个主要 CTA。
- 商品详情移动端不用滚很久就能找到“咨询 / 试香”入口。

## 阶段 3：SEO 和分享基础

### 目标

让网站能被搜索引擎和社交分享正确识别。

### 任务

1. 在 layout 中补基础 SEO：
   - `canonical`
   - Open Graph title / description / image
   - Twitter card
   - favicon
   - theme color
2. 增加 `robots.txt`。
3. 增加 `sitemap.xml`，只包含公开页面。
4. 商品详情页可补基础结构化数据，但试运营阶段不要标记成可直接在线购买的真实库存。
5. `admin.html`、会员订单、积分商城等非公开页面不进入 sitemap。

### 验收

- 首页、香水列表、商品详情、试香、关于我们都有合理 title 和 description。
- 分享链接时显示馥屿品牌名、简短描述和统一 OG 图。
- sitemap 不包含后台或开发版交易页面。

## 阶段 4：合规和信任内容

### 目标

补齐公开网站应有的基础说明，让用户知道如何咨询、购买、试香、退换和联系。

### 任务

1. 服务页补齐：
   - 配送说明。
   - 退换货说明。
   - 试香说明。
   - 正品来源说明。
   - 售后联系说明。
2. 关于我们补齐：
   - 馥屿定位。
   - 买手标准。
   - 客服方式。
   - 工作室预约方式。
3. 新增或补充法律 / 合规页面：
   - 隐私政策。
   - 用户服务协议。
   - 支付与人工购买说明。
4. 页脚增加这些公开链接。
5. 如果暂时没有公司主体信息，页面用待确认占位，但上线前必须替换。

### 验收

- 用户能在页脚找到客服、配送退换、隐私政策和用户协议。
- 页面不使用模糊承诺，例如“绝对最低价”“永久保真”。
- 正品来源说明具体但不过度承诺。

## 阶段 5：部署配置

### 目标

用最小稳定方式发布展示站。

### 推荐部署形态

第一版优先静态部署：

```text
Eleventy public build -> dist-public/ -> 静态托管 / CDN / HTTPS
```

可选平台：

- Vercel。
- Netlify。
- Cloudflare Pages。
- 对象存储 + CDN。

### 任务

1. 明确构建命令：

```bash
cd 网页制作
npm ci
npm run launch:check
```

2. 明确发布目录：

```text
网页制作/dist-public
```

3. 配置 HTTPS。
4. 配置自定义域名。
5. 配置 404 fallback 或静态 404 页面。
6. 配置缓存策略：
   - HTML 短缓存。
   - CSS / JS 可长缓存，但如果没有 hash 文件名，先不要设置过长。
7. 如果部署静态版，不部署 Node API 和后台。
8. 本地可使用 `npm run build:public` 生成公开发布包预览，不直接部署开发版 `dist/`。
9. 填入真实运营信息后运行 `npm run launch:strict`；部署平台也应使用这个命令作为 build command。
10. 部署后运行 `SITE_URL=https://你的正式域名 CONTACT_EMAIL=你的客服邮箱 CONTACT_WECHAT=你的客服微信 npm run check:live`。

### 验收

- 线上首页可访问。
- 线上公开页面链接可访问。
- 刷新商品详情页不会 404。
- 静态站不会调用缺失的支付 / 订单 API。
- 发布包不包含后台、会员、订单、积分页面或对应前端模块。

## 阶段 6：基础安全和质量检查

### 目标

即使是展示站，也不能有明显安全和质量缺口。

### 任务

1. 如果只部署静态站：
   - 不公开后台入口。
   - 不公开 API。
   - 不暴露本地开发密钥。
2. 如果部署 Node 服务：
   - `NODE_ENV=production`
   - 不配置开发用 `PAYMENT_WEBHOOK_SECRET`。
   - 不通过 `SEED_ADMIN_PASSWORD` 创建生产管理员。
   - cookie 使用 `Secure`。
   - 加安全响应头。
3. 检查外链打开策略，外部链接使用安全属性。
4. 检查表单不会静默失败。
5. 检查 404、空状态和接口失败文案。

### 验收

- 搜索项目中没有公开的 `dev-admin`、默认 webhook secret 或旧后台 key。
- 公开站点不暴露后台操作能力。
- 页面没有明显 JavaScript 报错。

## 阶段 7：上线前内容替换清单

### 说明

商品资料和图片本阶段现在不执行，当前外部图片和测试商品数据可以继续保留给开发测试用。真实运营信息不属于商品图片内容，正式公开前仍必须补齐。

### 运营信息

1. 正式域名 `SITE_URL`。
2. 客服邮箱 `CONTACT_EMAIL`。
3. 客服微信 `CONTACT_WECHAT`。
4. 经营主体名称 `BUSINESS_NAME`，可选，未设置时默认 `馥屿 Scent Atoll`。
5. 工作室试香预约方式 `STUDIO_BOOKING`，可选，未设置时默认 `通过客服微信预约`。
6. 客服时间 `CUSTOMER_HOURS`，未设置时默认 `12:00 - 20:00`。

### 图片

1. 替换首页 hero 图。
2. 替换商品图。
3. 替换品牌图。
4. 替换文章图。
5. 替换 OG 分享图。
6. 移除明显大牌瓶身、商标、包装露出图片，除非已有授权。
7. 图片压缩并上传到稳定地址。

### 商品

1. 商品名称。
2. 品牌名称。
3. 价格。
4. 容量。
5. 库存或咨询状态。
6. 香调结构。
7. 买手点评。
8. 适合场景。
9. 盲买提醒。
10. 试香套装规则。

### 合规

1. 真实配送范围。
2. 退换货规则。
3. 发票和售后说明。
4. 正品来源和采购凭证留档。
5. 独立域名备案要求。
## 最终验收清单

上线前逐项确认：

- `npm run launch:check` 通过。
- 填入真实运营信息后，`npm run launch:strict` 通过。
- 公开页面无横向溢出。
- 首页、香水列表、商品详情、试香、关于我们、服务页可访问。
- 商品详情主 CTA 指向咨询或试香，不进入失败支付。
- 页脚包含客服、配送退换、隐私政策、用户协议。
- `robots.txt` 和 `sitemap.xml` 正确。
- favicon 和 OG 图存在。
- 后台、会员订单、积分商城不在公开 sitemap 中。
- 没有明显大牌图或未授权图片。
- 如果决定正式发布真实商品，不能有测试商品名或测试价格残留。
- 没有测试客服、测试域名或经营主体占位残留。
- 线上 HTTPS 可用。
- 自定义域名可访问。
- 部署后 `SITE_URL=https://你的正式域名 CONTACT_EMAIL=你的客服邮箱 CONTACT_WECHAT=你的客服微信 npm run check:live` 通过。

## 推荐执行顺序

```text
1. 收口当前工作区
2. 调整试运营模式，避免支付 / 订单误导
3. 压缩移动端 header
4. 补 SEO / favicon / sitemap / robots
5. 补服务、隐私、协议、客服内容
6. 准备静态部署配置
7. 填入真实运营信息并跑严格检查
8. 店主侧替换真实图片和商品数据，或确认继续以测试内容做内部验收
9. 部署 `dist-public/` 并做线上验收
```

第 8 步属于运营内容准备，不是本轮工程、部署、SEO 和合规收口的阻塞项。正式公开推广前仍应替换真实图片和商品数据，尤其要避免未授权商标、瓶身或包装图片。

## 本阶段成功标准

馥屿可以作为一个公开的品牌展示和试香咨询网站上线。用户能理解品牌、浏览商品、判断气味方向，并知道如何联系或预约；但不会误以为已经进入完整在线支付电商系统。
